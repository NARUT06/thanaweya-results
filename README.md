# موقع نتيجة الثانوية العامة

موقع بحث عن نتائج الثانوية العامة بالاسم أو رقم الجلوس، مبني بـ **React + Vite + Tailwind CSS**، ومُصمم بحيث تقدر تستخدمه كل سنة من غير ما تلمس كود خالص — بس تستبدل ملف البيانات.

## المميزات

- 🔍 بحث بالاسم (جزء من الاسم كفاية) أو برقم الجلوس
- 🧠 بحث ذكي: `عبدالله` = `عبد الله` = `عبد-الله`، وبيتجاهل التشكيل ويوحّد أشكال الألف/الياء/الهمزة
- ⚡ سريع حتى مع مئات الآلاف من السجلات (البحث بيشتغل في Web Worker منفصل عشان الواجهة متتجمدش)
- 🧩 الأعمدة ديناميكية بالكامل — بتتقرأ من ملف الإكسل نفسه، مفيش أسماء حقول مكتوبة في الكود
- 📱 Responsive بالكامل (موبايل / تابلت / كمبيوتر)
- 🔁 قابل لإعادة الاستخدام كل سنة بخطوة واحدة بس (شرح تحت)

## هيكل المشروع

```
src/
  components/   SearchBox, StudentCard, ResultTable, Loading, NoResult
  pages/        Home.jsx
  hooks/        useSearchWorker.js   (نقطة الاتصال بين الواجهة والـ Worker)
  workers/      search.worker.js    (تحميل البيانات + البحث خارج الـ main thread)
  utils/
    normalizeArabic.js  ← خوارزمية توحيد النص العربي (هنا تظبط أي حاجة في البحث)
    searchEngine.js     ← منطق البحث نفسه (فهرسة + مطابقة)
    dataProvider.js     ← طبقة البيانات (فعليًا Excel→JSON، ممكن تتحول لـ API بسهولة)
scripts/
  convert-xlsx-to-json.mjs   ← سكريبت تحويل الإكسل لملف JSON (تشغّله كل سنة)
public/
  data.xlsx     ← حط ملف نتيجة السنة هنا (فيه بيانات تجريبية دلوقتي للتجربة)
  data.json     ← بيتولد تلقائيًا من السكريبت، ده اللي الموقع فعليًا بيقرأه
```

## التشغيل أول مرة

```bash
npm install
npm run dev
```

هيفتح على `http://localhost:5173` وهتلاقي بيانات تجريبية شغالة (7 طلاب) عشان تجرب البحث.

## إزاي تستخدم بياناتك الحقيقية (وكل سنة بعد كده)

1. احذف `public/data.xlsx` وحط ملف الإكسل بتاعك مكانه بنفس الاسم `data.xlsx`.
   - لازم أول صف في الملف يكون أسماء الأعمدة (الاسم، رقم الجلوس، المدرسة...الخ).
2. شغّل أمر التحويل:
   ```bash
   npm run convert-data
   ```
   هيطلعلك في الترمينال: عدد السجلات، الأعمدة اللي لقاها، وأنهي عمود اعتبره "الاسم" وأنهي عمود اعتبره "رقم الجلوس".
3. لو الاكتشاف التلقائي غلط (مثلاً اختار عمود غلط كاسم)، افتح `public/data.json`
   وعدّل قيمتين بس في أول الملف: `nameColumnIndex` و `seatColumnIndex` (index الأعمدة بيبدأ من 0).
4. `npm run dev` أو `npm run build` — خلاص، الموقع بقى شغال بالبيانات الجديدة.

**ده كل اللي محتاجه كل سنة.** مفيش أي تعديل في أي كود تاني.

> ملحوظة عن الحجم: مع بيانات كبيرة جدًا (مئات الآلاف من الصفوف)، تأكد إن السيرفر
> اللي هترفع عليه الموقع بيدعم Gzip/Brotli compression للملفات الثابتة (أغلب
> الاستضافات زي Netlify/Vercel/GitHub Pages بتعمل ده تلقائي) عشان ملف الـ JSON
> ينزل مضغوط وسريع.

## البناء للنشر (Build)

```bash
npm run build
```

هيطلعلك مجلد `dist/` فيه الموقع جاهز، تقدر ترفعه على أي استضافة static زي:

- **GitHub Pages** (طالما عندك GitHub، ده هيكون أسهل حل ومجاني)
- Netlify / Vercel / Cloudflare Pages (كلهم مجانيين ومباشرين برفع مجلد dist)

لو هترفعه على GitHub Pages تحت مسار زي `username.github.io/repo-name`، افتح
`vite.config.js` لو حصلت مشاكل في تحميل الملفات — القيمة الحالية (`base: './'`)
بتخليه يشتغل من أي مسار فرعي من غير تعديل عادةً.

## لو حبيت تطوّر الموقع بعدين

بما إن كل حاجة متقسمة بشكل منظم، إضافة الميزات دي هتكون سهلة نسبيًا:

- **بحث بالمحافظة/المدرسة**: ضيف dropdown في `SearchBox.jsx` وفلتر إضافي في `searchEngine.js`
- **طباعة/تصدير PDF لنتيجة الطالب**: زرار في `StudentCard.jsx` يستخدم `window.print()` كبداية بسيطة
- **صفحة تفاصيل لكل طالب برابط منفصل**: أضف `<Route path="/student/:seatNumber" ... />` في `App.jsx` (React Router متظبط بالفعل)
- **الانتقال من JSON لـ Backend حقيقي (API/قاعدة بيانات)**: كل التعديل هيكون جوه `dataProvider.js` بس، من غير ما تلمس أي component أو أي حاجة في الواجهة

## ملاحظة عن الأداء مع أعداد ضخمة (900 ألف+ سجل)

- البحث برقم الجلوس فوري (Map lookup، O(1))
- البحث بالاسم بيمسح كل الأسماء (O(n)) لكن جوه Web Worker منفصل، فالواجهة مش بتتجمد وقت الكتابة
- في التجربة عادةً البحث بيرجع في أقل من نص ثانية حتى مع مئات الآلاف من السجلات على أي جهاز حديث
- لو حسيت إن الأداء مش كفاية مع العدد الحقيقي عندك، الخطوة الطبيعية الجاية هي نقل البحث لسيرفر خلفي (Backend) بدل المتصفح — والمعمارية الحالية مُجهّزة لده أصلاً عن طريق `dataProvider.js`
